# Cơ sở dữ liệu

> **Tài liệu tham chiếu cũ.** Luật hiện hành: [rules/RULE-DATABASE.md](rules/RULE-DATABASE.md), [../db/README.md](../db/README.md). Bảng §2 dưới đây dùng **đánh số migration lịch sử** (0001–0067), đã gộp thành 9 tệp gốc `db/migrations/000x_goc_*.sql` ngày 23/10/2026; đọc để biết bảng ra đời vì sao, không dùng để tìm tệp.

PostgreSQL 16. Khai báo nằm ở `db/migrations/*.sql` (mỗi bảng có `COMMENT`), kiểu TypeScript tương ứng ở `apps/api/src/db/types.ts`.

## 1. Quy ước

- Mọi bảng nghiệp vụ có `tenant_id` (đơn vị). Mã nghiệp vụ duy nhất trong một đơn vị: `UNIQUE (tenant_id, code)`.
- **Khoá chính**: cột `id bigint GENERATED BY DEFAULT AS IDENTITY` (số tự tăng 1, 2, 3…); bảng tổng hợp dùng khoá ghép. API trả id dạng chuỗi số (`"123"`), đường dẫn `/…/:id` chỉ nhận số.
- **Mã của hệ thống bên ngoài không làm khoá chính**, mà nằm ở cột riêng để đối chiếu và cập nhật khi nguồn thay đổi:

  | Bảng | Cột đối chiếu | Ví dụ |
  |---|---|---|
  | `accounting_events` | `doc_key` (duy nhất trong đơn vị), `source_system` | `btsoft:95:sale:671` |
  | `branches` | `code` = mã shop, `external_ref` | `26001`, `blog:95` |
  | `partners` | `code` = mã khách / nhà cung cấp ở hệ thống nguồn | `0912345678` |
  | `products` | `sku` | `100861007` |
  | `accounts` | `code` = số tài khoản | `5111` |

  Join trong cơ sở dữ liệu luôn qua `id`; tra cứu từ hệ thống nguồn qua cột đối chiếu.
- Tham chiếu tới tài khoản bằng **mã** qua khoá ngoại ghép `(tenant_id, account_code)` — đọc dữ liệu thấy ngay số tài khoản.
- Tiền `numeric(18,2)`; ngày hạch toán `date`; thời điểm `timestamptz`.

## 3. Quan hệ chính

```
tenants ─┬─ branches ────────────┐
         ├─ accounts ──────────┐ │
         ├─ partners ────────┐ │ │
         │                   │ │ │
         └─ accounting_events ┼─┼─┼──► ledger_entries ──► ledger_lines ──► (cộng dồn) ledger_balances_daily
                 │           │ │ │        ▲
                 │           └─┴─┴────────┘
                 └──► tax_invoices ──► tax_invoice_lines
```

- Một `accounting_events` sinh một `ledger_entries` cho **mỗi bộ sổ** nó vào.
- `ledger_entries.reverses_entry_id` trỏ về bút toán bị đảo; bút toán bị đảo có `status = 'reversed'`.
- `tax_invoices` duy nhất theo `event_id`, luôn phản ánh phiên bản mới nhất.

## 4. Ràng buộc ở tầng database

| Ràng buộc | Cách làm |
|---|---|
| Bút toán phải cân | Trigger hoãn `ledger_lines_balanced`: cuối giao dịch tổng Nợ phải bằng tổng Có |
| Mỗi dòng đúng một bên | `CHECK ((debit = 0) <> (credit = 0))` |
| Sổ cái chỉ thêm | Trigger `ledger_lines_no_update` chặn `UPDATE/DELETE`; `ledger_lines_no_truncate`, `ledger_entries_no_truncate` chặn `TRUNCATE` |
| Mỗi bút toán chỉ bị đảo một lần | Chỉ mục duy nhất `ledger_entries_reversed_once` trên `reverses_entry_id` |
| Số âm chỉ ở bút toán đảo | Trigger `ledger_lines_negative_guard` |
| Chỉ một nhóm hạch toán mặc định | Chỉ mục duy nhất có điều kiện |
| Tài khoản phải tồn tại | Khoá ngoại ghép `(tenant_id, account_code)` |
| Kỳ không vắt năm | `CHECK` trên `fiscal_periods` |

Phép thử `apps/api/test/db-rules.test.ts` ghi thẳng vào bảng (bỏ qua tầng nghiệp vụ) để chắc các trigger, ràng buộc trên còn chặn được.

## 5. Số dư

`ledger_balances_daily` giữ phát sinh cộng dồn theo `(bộ sổ, chi nhánh, tài khoản, ngày, đối tượng)`.

- Cập nhật bằng `INSERT … ON CONFLICT … DO UPDATE` trong cùng giao dịch ghi `ledger_lines`.
- `partner_id = 0` nghĩa là không theo đối tượng; chỉ khác 0 với tài khoản theo dõi đối tượng hoặc lưỡng tính.
- Số dư tại ngày D = tổng `debit − credit` các dòng có `posting_date ≤ D`.
- Bút toán ghi số âm cộng số âm vào đúng ngày gốc → số dư và số phát sinh tự về đúng.

## 6. Thêm hoặc đổi bảng

1. Tạo `db/migrations/NNNN_mo_ta.sql` (số kế tiếp). Viết `COMMENT ON` cho bảng, cột mới.
2. Cập nhật `apps/api/src/db/types.ts`.
3. Chạy `npm run db:migrate` (API cũng tự chạy khi khởi động).
4. Không sửa tệp migration đã chạy ở môi trường thật.

## 7. Khi dữ liệu lớn

Thiết kế sẵn cho: chia `ledger_entries`, `ledger_lines`, `ledger_balances_daily` theo năm của `posting_date` (partition); báo cáo tổng hợp chỉ đọc `ledger_balances_daily`; chỉ mục `(tenant_id, account_code, posting_date)`.
